# Лабораторная работа 03. Отчёт

## Вариант 23: Рейтинги игр/фильмов с кэшированием и обновлением

### Описание реализации

Было создано одностраничное веб-приложение для просмотра рейтингов фильмов и игр с возможностью поиска, пагинации и кэширования данных.

#### Архитектура приложения

- **HTML (index.html)**: Структура страницы с заголовком, полем поиска, кнопкой обновления, областью статуса и списком элементов.
- **CSS (styles.css)**: Современный responsive дизайн с анимациями загрузки (skeleton), состояниями loading/error/empty.
- **JavaScript (main.js)**: Логика приложения с использованием async/await, fetch API, AbortController, кэшированием.
- **Данные (data.json)**: Mock-данные с 20 элементами (фильмы и игры) с рейтингами, описаниями и изображениями.

#### Ключевые компоненты

1. **fetchWithRetry функция**
   - Поддержка повторных попыток (retries)
   - Экспоненциальная задержка (backoff)
   - Таймаут запроса
   - Интеграция с AbortController для отмены

2. **Кэширование**
   - In-memory кэш с TTL (5 минут)
   - Fallback в localStorage для персистентности
   - Возможность принудительного обновления (кнопка "Обновить")

3. **Управление состоянием**
   - Loading: skeleton анимация
   - Error: отображение ошибки с кнопкой повтора
   - Empty: сообщение при отсутствии результатов
   - Success: отображение списка с пагинацией

4. **UX улучшения**
   - Дебаунс поиска (300ms)
   - Отмена предыдущих запросов при новом поиске
   - Lazy loading изображений
   - Responsive дизайн

### Запуск приложения

1. Перейдите в директорию `src/`
2. Запустите локальный сервер:
   ```bash
   python -m http.server 8080
   ```
3. Откройте в браузере: `http://localhost:8080`

### Описание кэш-подхода

#### Реализация кэша
- **Тип кэша**: In-memory Map с TTL + localStorage fallback
- **TTL**: 5 минут
- **Ключ кэша**: `items_${searchQuery}` - зависит от поискового запроса
- **Инвалидация**: Принудительная через кнопку "Обновить" или истечение TTL

#### Поведение в Network
- **Первый запрос**: HTTP GET к data.json, статус 200, время загрузки ~100-500ms
- **Кэшированные запросы**: Отсутствие сетевых запросов, мгновенная загрузка из памяти/localStorage
- **Обновление**: Принудительная инвалидация кэша, повторный запрос к серверу

#### Преимущества подхода
- Снижение нагрузки на сервер
- Улучшение UX (быстрая загрузка)
- Работа оффлайн (частично, через localStorage)
- Простота реализации

### Описание ретраев/таймаутов/отмены

#### fetchWithRetry функция
```javascript
async function fetchWithRetry(url, options = {}) {
    const { retries = 3, backoffMs = 1000, timeoutMs = 5000, signal } = options;
    // ... реализация с циклами попыток и таймаутами
}
```

#### Параметры
- `retries`: Количество повторных попыток (3 по умолчанию)
- `backoffMs`: Начальная задержка между попытками (1000ms, экспоненциально растёт)
- `timeoutMs`: Максимальное время на запрос (5000ms)
- `signal`: AbortSignal для отмены

#### Отмена запросов
- **При новом поиске**: Предыдущий запрос отменяется через AbortController
- **Дебаунс**: Задержка 300ms перед отправкой запроса
- **Обработка AbortError**: Корректная обработка отменённых запросов

#### Таймауты и ретраи
- Таймаут на каждый запрос: 5 секунд
- При ошибке: ожидание 1s, 2s, 4s перед повторными попытками
- Максимум 3 повторные попытки + первоначальный запрос
